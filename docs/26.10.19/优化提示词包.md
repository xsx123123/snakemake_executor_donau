# 提示词包：Snakemake Donau 执行器优化

配套《snakemake_executor_donau_优化方案.md》使用。每个提示词可独立复制给 AI 编码助手（Cursor / Claude Code / Copilot 等）。

## 使用说明

1. 先 `git clone https://github.com/xsx123123/snakemake_executor_donau.git` 到本地；
2. 把提示词中的占位符替换为实际值：
   - `{REPO_PATH}` → 仓库本地绝对路径（如 `/home/user/work/snakemake_executor_donau`）
   - `{DOC_PATH}` → 优化方案文档绝对路径
   - `{CLUSTER}` → 测试集群名称 / 队列名（如 `fat_x86`）
3. **按顺序执行**：提示词 1（基线）→ 2（Phase 1）→ 3（Phase 2）→ 4（插件适配）→ 5（压测验收）；提示词 0（总控）可替代 1–5 一次性下发；
4. 每个阶段完成后要求 AI 报告实测数据并留存，不要跳过基线直接优化；
5. 若没有真实 Donau 集群，提示词 3 内置了 mock CLI 方案，可在任何 Linux 机器上完成开发与测试。

## 提示词 2：Phase 1 纯 Python 并发提交优化

````text
你是资深 Python 工程师，正在优化仓库 {REPO_PATH} 的 Snakemake Donau 执行器插件（华为 Donau 调度器）。当前问题：run_job 串行调用 dsub（executor.py 第 167 行经 _run_cmd_with_retry 同步 subprocess.check_output），万级任务提交要几十分钟。基线数据见仓库根目录 baseline.md。

请实现以下优化（严格按此顺序）：
1. 提交并发化（核心）：
   - 将 run_job 拆分为「构造作业描述 _build_submit_request(job)」+「实际 dsub 提交 _submit_worker(req)」，映射逻辑原样保留；
   - 用 ThreadPoolExecutor(max_workers=N) + 有界队列实现有界并发提交；run_job 保持同步：提交任务到线程池后阻塞等待该 job 的 external_jobid，再调用 report_job_submission（接口契约不变）；
   - 保留 _run_cmd_with_retry 的 3 次重试 + 退避语义；
   - 新增插件设置 --donau-submit-concurrency（默认 16，上限 64），在 __init__.py 的 ExecutorSettings 中注册（pydantic Field + metadata help）。
2. 失败诊断并行化：_get_job_diagnostics 用 asyncio.gather 并发拉取多个 djob -ll；失败仍返回空 dict，不影响主流程。
3. 轮询与心跳保持不变（_get_donau_job_status_async 的批量双查询逻辑禁止改动）。

硬性约束：
- 不得改变 Snakemake 插件接口契约（RemoteExecutor、pydantic settings、entry point、check_active_jobs 语义、状态判定集合）；
- 不得改变 dsub 资源映射语义与参数输出；
- 兼容 Python 3.8（禁止 walrus、match、内置泛型等 3.9+ 语法）；
- 线程池必须可控：并发度设置、优雅关闭（插件退出时 shutdown，避免泄漏 dsub 进程）；
- 并发提交要防止线程安全问题：日志、状态、计数器加锁或用 queue 串行化。

验证与验收：
- 用 Test/snakefile（可临时把 SAMPLES 扩到 1000）跑通：snakemake --snakefile Test/snakefile --executor donau --jobs 100 --latency-wait 60；
- 对比 baseline.md：1000 任务提交阶段耗时 ≤ 基线 1/5，或达到调度器吞吐上限（记录上限值）；
- 状态零误判：抽样 500 个作业与 djob 真值比对；
- 命令行兼容性：--executor donau 及原插件参数全部可用。
产出：改动后的代码 + 一份对比数据表（基线 vs 优化后）+ 变更说明。
````

## 提示词 3：Phase 2 Rust sidecar 常驻代理（主体）

````text
你是资深 Rust 工程师（tokio 生态），正在为仓库 {REPO_PATH} 的 Snakemake Donau 执行器插件开发常驻代理 donau-sidecar。设计文档见 {DOC_PATH} 第 5 节（Sidecar 详细设计），必须严格遵循。目标：把提交管线、批量轮询、状态落盘恢复下沉到 Rust，插件只做协议转发。

请实现：
1. 工程结构（仓库内新建 rust/ 目录）：
   - Cargo.toml：依赖 tokio、serde、serde_json、tracing、clap、anyhow；
   - src/main.rs（入口与生命周期）、src/protocol.rs（JSON Lines 协议与握手）、src/donau.rs（dsub/djob/dkill 调用、输出解析、3 次重试+退避）、src/state.rs（状态机+journal 落盘/恢复）、src/scheduler.rs（提交信号量、轮询 interval、背压 channel）、src/metrics.rs（指标与 heartbeat）。
2. 协议（严格按设计文档 §5.2）：stdin/stdout JSON Lines；
   - 插件→sidecar：hello(握手,proto=1) / submit / poll / cancel / diag / shutdown；
   - sidecar→插件：hello / submitted / submit_failed / states / diag / canceled / heartbeat(30s) / error；
   - 单条消息解析失败只丢弃该条并记日志；协议版本不符返回 error 并退出（由插件降级）。
3. 并发与背压（§5.3）：tokio 多线程 runtime；Semaphore(N) 有界并发提交（N 默认 32，命令行可配）；单一 interval 任务做批量轮询（默认 5s）；对全部活跃作业先 1 次 djob，缺失 ID 追加 1 次 djob -D（与现有插件语义一致）；插件请求经有界 channel（1024）。
4. 状态与落盘（§5.4）：状态枚举 SUBMITTED/ACTIVE/FINISHED/FAILED/CANCELLED/UNKNOWN；journal 为 JSON Lines 追加写（donau_sidecar.journal，50MB 轮转保留 7 天）；提交/终态 fsync，运行中状态 1s 批量落盘；启动时读 journal 重建状态，对未终结作业用 djob 对账，输出恢复摘要。
5. 命令构造（§5.2 submit 字段 → dsub）：严格保持与现插件一致的资源映射（threads→-R cpu、mem_mb→-R mem、runtime→-T 秒、queue→-q 需配合 -aa、priority→-p、nodes→-N、exclusive→-x job、tag→--tag、account→-A、mpi→--mpi、npu/gpu→-R 拼接、extra_args→shlex 拆分透传、-n 作业名与 63 字符截断、-oo 日志、--cwd）；作业名规则 smk_{name}_{wildcards}_{jobid}_{uuid6} 不变。
6. 测试（重点，无集群也可全绿）：
   - DONAU_BIN_DIR 环境变量指向 mock 脚本目录；提供 tests/fixtures/ 下的 mock dsub / djob / dkill 脚本（支持 -o "jobId state" --no-header、-D、-ll，用固定数据返回）；
   - Rust 单元测试 + 集成测试：提交成功/重试耗尽、轮询批量与 -D 兜底、取消、崩溃恢复（模拟 journal 存在）、协议握手失败；
   - cargo test 必须全绿；输出测试覆盖率概览。

硬性约束：
- sidecar 不感知 Snakemake，不引入任何 Python 依赖；
- 不改变状态判定集合与作业命名/映射语义（与方案文档一致）；
- 错误处理：任何外部命令失败不得 panic，必须记录并走定义的降级路径；
- 日志走 stderr（tracing），stdout 只用于协议，严禁混用。

验收：cargo build --release 通过；cargo test 全绿；README 或 docs/ 中补充 sidecar 的构建与配置说明。
````

## 提示词 4：插件侧薄客户端与联调

````text
你是资深 Python 工程师，为仓库 {REPO_PATH} 的 Snakemake Donau 执行器插件接入已实现的 Rust sidecar（见 rust/ 目录与 {DOC_PATH} 第 5 节）。

请实现：
1. 新增 snakemake_executor_plugin_donau/sidecar_client.py：
   - spawn：__post_init__ 时按 --donau-sidecar-path（缺省探测插件包内/同目录 donau-sidecar 二进制）用 subprocess.Popen(stdin=PIPE, stdout=PIPE, stderr 转发到日志) 拉起；发 hello 握手（30s 超时），协议版本不符则降级；
   - 请求/响应：submit / poll / cancel / diag 的 JSON Lines 收发，统一 30s 超时；sidecar 无响应或进程退出 → 自动重启（≤3 次）→ 仍失败则降级 legacy 模式并打 WARNING；
   - 优雅关闭：插件退出（atexit / 信号）时发 shutdown，等待退出；
   - 背压：sidecar channel 满时请求阻塞等待（不丢任务）。
2. 改造 executor.py：
   - run_job 改为：构造 submit 请求 → sidecar_client 提交并等待 submitted/submit_failed → 拿到 donau_jobid 后 report_job_submission（接口契约不变）；sidecar 不可用时回退到 Phase 1 线程池路径；
   - check_active_jobs 改为：向 sidecar 发 poll，用返回的 states 走原状态判定逻辑（成功/失败/保持活跃、失败自动 diag、心跳日志全部保留）；
   - cancel_jobs 改为：向 sidecar 发 cancel。
3. __init__.py 的 ExecutorSettings 新增：sidecar_path(str,None)、sidecar_mode("auto"/"legacy"/"sidecar"，默认 auto)、recover_orphans(bool, False)；metadata 写明 help。
4. 联调测试（无真实集群）：
   - 用提示词 3 提供的 mock CLI（DONAU_BIN_DIR）跑端到端：snakemake --snakefile Test/snakefile --executor donau --jobs 10 --latency-wait 60；
   - 覆盖：sidecar 正常路径、sidecar 缺失（自动降级 legacy）、sidecar 中途被杀（重启+降级）、崩溃恢复（kill -9 插件后重启，sidecar journal 恢复对账）。

硬性约束：
- 不改变插件对外命令行兼容性与状态判定集合；legacy 路径必须完整保留可用；
- Python 3.8 兼容；线程安全（sidecar 客户端内部用锁/单线程事件循环管理连接）；
- 日志与心跳格式与现插件保持一致，便于用户无感切换。

验收：mock 环境端到端跑通 100 任务；降级、恢复、重启三类故障注入测试全部通过并有日志证据；命令行兼容性回归通过。
````
